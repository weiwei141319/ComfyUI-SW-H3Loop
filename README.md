# ComfyUI-SW-H3Loop

**海螺 H3「一采循环」长视频专用循环节点包** —— 完全替代官方 `StartLoop` / `EndLoop`。

面向 MiniMax H3（海螺）音视频联合生成模型：**用一次采样（一采）把 15 秒级的单段生成
接成 30 秒以上的长视频**，并保证段与段之间在视觉上无缝、在音频上连续。

> 官方 `StartLoop` 只给循环体一个整数 `i`，所有随轮次变化的量只能写成 `f(i) = i × 固定系数`。
> 本包把「轮数 / 本轮序号 / 是否首轮 / 本轮音频绝对起点秒 / 本轮时长秒」全部算好再交给循环体，
> 循环体内每个节点拿到的都是**绝对量**。

---

## 为什么能替代官方循环节点

ComfyUI 的循环机制**不认节点名，只认 schema 上的 `loop_boundary` 声明**：

```python
# execution.py:1180
boundary = class_def.GET_SCHEMA().loop_boundary \
           if issubclass(class_def, _ComfyNodeInternal) else None
if boundary == "start":   start_nodes.add(node_id)
elif boundary == "end":   end_nodes.add(node_id)
```

所以只要节点是 `_ComfyNodeInternal` 子类（新版 API `io.ComfyNode`）并声明
`loop_boundary="start"` / `"end"`，框架就会把它当作循环边界。

⚠️ **必须用新版 API**。经典 API（`INPUT_TYPES`）的 class 不是 `_ComfyNodeInternal` 子类，
`GET_SCHEMA()` 取不到，声明无效。

## 安装

```bash
cd <你的 ComfyUI 路径>/custom_nodes
git clone https://github.com/weiwei141319/ComfyUI-SW-H3Loop.git
# 或直接把整个 SW_H3Loop 文件夹拷进 custom_nodes/
```

**然后重启 ComfyUI**（`custom_nodes` 只在启动时加载），在节点面板搜 `SW H3`。

## 节点一览（9 个）

| 节点 | 作用 | 位置 |
|---|---|---|
| **SW H3 循环·起点** | 循环边界 `start`，输出轮数/本轮序号/是否首轮/本轮绝对起点秒/本轮时长秒 | 循环外 |
| **SW H3 本轮计划** | 把上面的绝对量整理成本轮可用的参数 | 循环体内 |
| **SW H3 音频切片（绝对起点）** | 按**绝对起点秒**切片，越界自动补静音 | 循环体内 |
| **SW H3 去重（视听同步）** | 丢掉每轮开头 K 帧（钉帧），含首轮参考图种子 | 循环体内 |
| **SW H3 接力帧选择（循环体内）** | 选本轮的 AddGuide 钉帧：首轮=参考图种子，其余=上轮末 K 帧 | 循环体内 |
| **SW H3 累积（循环体内）** | 跨轮累积 carry（图 + 音） | 循环体内 |
| **SW H3 循环·累积出栈** | 循环边界 `end`，把累积结果送出循环 | 循环外 |
| **SW H3 拆包(carry→图/音)** | 把 carry 的 `[图, 音]` 拆成两路 | 体内/体外均可 |
| **SW H3 帧算术速算** | 纯 CPU 算帧账：段数 / 步长 / 各段起点，前端 JS 同步显示 | 循环外 |

## 核心机制

### 1. 钉 K 帧 ≡ 丢 K 帧（融合对齐的充要条件）

```
段1 生成 277 帧，末 22 帧 = 帧号 255…276
        ↓ SW H3 接力帧选择（第 2 轮：取累积末 22 帧）
接力帧 = 帧号 255…276
        ↓ MiniMaxH3AddGuide 钉在段2 开头
段2 前 22 帧 ≈ 帧号 255…276（与段1 末 22 帧内容相同）
        ↓ SW H3 去重 丢开头 22 帧
段2 从帧号 277 开始进成片
        ↓
段1 末帧(276) → 段2 首帧 = 成片第 255 帧   ✅ 无缝，且 255…276 只保留一份
```

### 2. ★ 首轮也必须丢 K 帧

首轮 `AddGuide` 钉的 K 帧是 **「参考图 × K」的种子**（不是模型生成的内容）。
不丢它，成片开头就会出现约 1 秒完全静止的参考图。

| 轮次 | 前 K 帧是什么 | 该不该丢 |
|---|---|---|
| 首轮 | **参考图种子**（无时间含义） | ✅ 必须丢 |
| 其余轮 | 上一轮真实末帧（有重叠时间含义） | ✅ 必须丢 |

→ **成片帧数 = `N × (L − K)`**

### 3. 越界补静音（绝不回绕）

切片请求超过音频剩余长度时，用 0 采样补齐到请求时长。
若改用「把歌拼 N 遍凑长度」的老做法，末段切片会越过单遍歌长、**落到下一遍拷贝的开头**
—— 成片最后一小段又唱回第一句。**张量不回绕、不报错，属静默出错。**

### 4. 空串容错

ComfyUI 前端会把「已勾选转成输入、但还没连线」的 widget 槽序列化成**空字符串 `''`**，
后端 `float('')` / `int('')` 直接抛异常、整条 prompt 作废。
本包所有 `execute` 入口都用 `_as_*` 系列容错，Combo 的 `options` 内含空串哨兵。

## 帧率硬约束（来自官方源码）

| 项 | 值 | 出处 |
|---|---|---|
| `FPS` | `24` | `comfy_extras/nodes_minimax_h3.py` |
| `AUDIO_LATENT_FPS` | `40` | `comfy/ldm/minimax/audio_vae.py`（`32000 / 800`） |
| `FRAME_RESCALE` | `5/3` | `comfy/ldm/minimax/model.py` |
| **视频合法帧数** | `5 + 17n` | `align_frame_count()` |
| **AddGuide 合法钉帧数** | `1` 或 `5 + 17n` | `MiniMaxH3AddGuide` |

**段起点只能落在整数像素帧上 → 只能落在 `n/24` 秒的格点上。**

因此「步长正好 10.0 秒」是**数学上无解**的（`L − K = 240` 与 `L ∈ 5+17n` 无交集），
详见 [`帧数账本.md`](帧数账本.md)。

## 默认参数（30 秒示例）

`L = 277 帧` / `K = 22 帧` / `N = 3 段` / 步长 `255 帧 = 10.6250 s`

| 段 | 像素帧起点 | 秒起点 | 进成片帧数 |
|---|---|---|---|
| 段1 | 0 | 0.0000 s | 255 |
| 段2 | 255 | 10.6250 s | 255 |
| 段3 | 510 | 21.2500 s | 255 |
| **合计** | | | **765 帧 = 31.8750 s** |

## 已知限制

- 仅针对 **MiniMax H3** 系列模型（依赖 `MiniMaxH3AddGuide` 的钉帧行为与 H3 的帧率网格）。
- 「一采」意味着**整段长视频共用一次采样调度**；分段之间的画面连续性依赖 AddGuide 钉帧，
  不能像「二采」那样对每段独立重采样。
- 循环体必须闭合在 `SW H3 循环·起点` → `SW H3 循环·累积出栈` 之间；
  没有下游的 `OUTPUT_NODE`（如 `PreviewImage` / `SaveVideo`）必须放在 `EndLoop` 之后。
